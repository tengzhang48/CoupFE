A compact finite-element core for custom operators.

CoupFE is a small, tested scaffold for developing custom operators, generated elements, contact formulations, and standalone solver paths. Applications keep ownership of model setup, mesh-tool adapters, domain semantics, and output policy.

The core contract

Compose the physics; keep the driver generic.

Bulk elements, contact, inertia, and loads contribute through the same interface. The assembly and solve layers do not need to know their application-specific meaning.

Drivers

Increment and solve

Newton increments, line search, implicit dynamics, and explicit linear-solver policy.

∂

One residual as source of truth

Supported smooth generated elements derive consistent tangents by complex-step differentiation. Analytic and semismooth operators keep their own separately tested tangent paths.

✓

Evaluation is separate from commit

Compiled elements keep trial evaluation separate from committed state. Generic accepted-step orchestration is not yet complete for every failure and multi-increment path.

P

Exact affine reduction

Core supplies the mesh-agnostic transformation U = Pq + U0 for serial quasistatic solves. Applications construct the physical relations; MPI and dynamics coverage is not claimed.

Build-time code generation

One supported formulation, two parallel backends.

A declared residual can produce source for an established Abaqus workflow and for CoupFE's open standalone runtime. Neither backend calls the other.

Established-solver target

Abaqus UEL

Abaqus owns the real procedure context, including LFLAGS. Current UEL generation is scoped to documented normal implicit/static use. Material declarations can separately generate Abaqus UMAT source; that output does not have a parallel native-UMAT host in CoupFE.

Standalone target

CoupFE native kernel

The f2py runtime exposes joint residual/tangent evaluation and, where generated, an explicit residual-only entry for serial or distributed callers.

Evidence boundary: agreement between native and UEL kernels can detect generation, sign, ordering, state-transfer, and ABI drift. Because both share a formulation, parity is an implementation check—not independent physical validation of the equations, parameters, or model.

A deliberate boundary

Core owns reusable numerical contracts.

The application remains responsible for the engineering model around those contracts. This keeps Core small without treating integration work as trivial. No general mesh-software adapter is part of Core.

Core does not provide a general CAD, Gmsh, DMPlex, Abaqus-input, or results-file adapter.

Read the complete capability matrix

Core owns

  • operator composition and sparse assembly;
  • serial drivers and scoped PETSc/MPI paths;
  • compiled-element evaluation and state interfaces;
  • affine algebra, compact mesh views, and regular-mesh utilities;
  • contact operators and search primitives; and
  • build-time UEL, UMAT, and native-kernel generation.

Applications own

  • authoritative geometry and mesh-tool integration;
  • physical labels, materials, loads, and boundary semantics;
  • units, parameter provenance, and loading protocols;
  • vendor formats, CAD association, and result translation;
  • model-specific verification and validation; and
  • outputs, review records, and engineering decisions.

Distributed execution

Rerunnable PETSc/MPI smoke programs are included.

The public paths cover scoped bulk, contact, dynamics, friction, and serial-versus-rank diagnostics. No retained final-revision multi-rank qualification or scaling record is published. There is also no retained large-scale benchmark or general performance claim.

Start with the small path

Install, run one example, then inspect its evidence boundary.

The base package needs NumPy and SciPy. Compiled elements need a compatible Fortran toolchain; code generation and PETSc/MPI are optional environments. This static website does not run CoupFE in the browser. 

git clone https://github.com/tengzhang48/CoupFE.git
cd CoupFE
pip install -e ".[dev,runtime,codegen,performance]"
python examples/linear_bar/run.py
python -m pytest -q -m "not slow"
